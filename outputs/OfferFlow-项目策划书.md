# OfferFlow 求职进度管理平台

## 1. 项目定位

面向高校求职者的 Web 应用。用户可以集中记录岗位投递、跟进面试状态、沉淀面试复盘，并通过数据面板观察求职节奏。

这是一个业务型管理系统，而不是单纯展示页面：它包含明确的用户、数据、状态流转、检索筛选和统计场景，适合作为初级前端、实施、测试或全栈方向的作品集项目。

## 2. 技术方案

| 层级 | 方案 | 本项目要证明的能力 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、TypeScript、Vue Router、Pinia、Element Plus | 组件化、状态管理、路由、表单与响应式页面 |
| 后端 | Java 17、Spring Boot、Spring Web、Spring Data JPA、Spring Security | REST API、分层结构、参数校验、认证授权 |
| 数据库 | MySQL 8 | 表结构设计、关联查询、索引与数据迁移 |
| 工程化 | Git、Swagger/OpenAPI、Docker Compose（可选） | 版本控制、接口文档、可复现部署 |

## 3. 核心用户故事

1. 用户注册并登录后，只能访问自己的求职记录。
2. 用户创建一条投递记录，填写公司、岗位、来源、薪资范围、投递时间和备注。
3. 用户在看板中将记录移动到“已投递、笔试、面试、Offer、已拒绝”等阶段。
4. 用户为面试添加复盘，包括轮次、问题、回答、结果和改进点。
5. 用户按阶段、城市、职位关键词、日期筛选记录。
6. 用户在仪表盘看到投递总数、各阶段数量、近 30 天投递趋势和 Offer 转化率。

## 4. 第一版范围（MVP）

### 必做

- 邮箱/用户名注册、登录、退出
- 岗位记录的新增、编辑、删除、详情
- 求职阶段看板与阶段更新
- 搜索、筛选、分页
- 面试复盘的新增、编辑、删除
- 数据仪表盘
- OpenAPI 接口文档、README、演示账号与种子数据

### 两周内不做

- 文件上传与简历解析
- AI 自动改简历或自动模拟面试
- 实时聊天、通知推送、多人协作
- 爬虫抓取招聘平台数据

这些功能会显著扩大开发和合规风险，先不纳入作品集第一版。

## 5. 数据模型

| 表 | 关键字段 | 关系 |
| --- | --- | --- |
| users | id、username、email、password_hash、created_at | 一个用户拥有多条 applications |
| applications | id、user_id、company、position、city、source、status、applied_at、salary_min、salary_max、note | 一条申请拥有多条 interviews |
| interviews | id、application_id、round、interviewed_at、result、questions、reflection | 属于一条 applications |

建议索引：`applications(user_id, status)`、`applications(user_id, applied_at)`、`interviews(application_id)`。

## 6. 页面与接口

| 页面 | 核心功能 |
| --- | --- |
| 登录/注册 | 表单校验、认证、错误反馈 |
| 仪表盘 | 指标卡、阶段分布、投递趋势 |
| 求职看板 | 按状态分列、快速更新状态 |
| 投递列表 | 搜索、筛选、分页、编辑删除 |
| 投递详情 | 公司与岗位信息、面试复盘列表 |
| 复盘编辑 | 面试轮次、问题、结论、改进项 |

API 按资源设计：`/api/auth`、`/api/applications`、`/api/applications/{id}/interviews`、`/api/dashboard`。

## 7. 两周冲刺排期

| 时间 | 交付物 | 验收标准 |
| --- | --- | --- |
| 第 1-2 天 | 项目初始化、数据库安装、原型、表设计 | 前后端可运行；数据库可连接；确认页面结构 |
| 第 3-4 天 | 认证与投递记录后端 API | Swagger 可完成注册、登录和投递记录 CRUD |
| 第 5-6 天 | 前端认证、列表、表单 | 可用界面完整调用 CRUD API |
| 第 7-8 天 | 看板、筛选、详情、面试复盘 | 用户可完成一条完整投递跟踪流程 |
| 第 9-10 天 | 仪表盘、异常处理、测试 | 种子数据下指标正确；关键流程有测试 |
| 第 11-12 天 | UI 打磨、响应式适配、README | 桌面和手机宽度可用；文档可复现启动 |
| 第 13-14 天 | 部署、录屏、简历材料 | 有公开演示或可本地演示；可讲清项目设计 |

## 8. 质量要求

- 不伪造业务数据、用户量或团队协作经历。
- API 返回统一错误格式；前端明确显示加载、空数据和错误状态。
- 密码只存哈希；接口按当前登录用户隔离数据。
- 每次提交使用小而清晰的 Git commit。
- README 说明技术栈、架构、启动步骤、核心截图、接口文档和已知限制。
